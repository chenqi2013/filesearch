# EmbeddingRWKV Tiny

- Source: https://github.com/howard-hou/EmbeddingRWKV
- Checkpoint: `rwkv0b1-emb-curriculum.pth`
- Runtime asset: text-only ONNX graph with the official `[RETR]` head and fused native WKV operators
- Tokenizer: RWKV World Tokenizer with EOS token `65535`
- Output dimension: 768
- Context: at most 1,024 tokens including the single EOS; all document windows are retained
- CPU quantization: per-channel dynamic INT8 FFN projections in layers 3–11 and attention output projections in layers 6–11 (zero based); other paths remain FP32
- ONNX SHA-256: `b2cfe70957dcabd96c85ab8d4c4928060fd060d74420b562b30889a8f818bead`
- Search vector/cache profile: `rwkv7-tiny-ffn3-attnout6-int8-structured-full-passages-v10`
- License: see `LICENSE-EmbeddingRWKV.txt`

The ONNX graph excludes the checkpoint's unused vision tower. Its recurrent WKV-7 blocks are exported as `com.localfind::Rwkv7` operators and executed by the Rust search core, avoiding the slow per-token ONNX `Loop` graph. It is generated by `scripts/export-embedding-rwkv.py` and verified against the official PyTorch implementation before export.

Run `scripts/quantize-embedding-rwkv.py --input <FP32 export> --output <model.onnx>` with its defaults for this CPU configuration. The previous v9 graph quantized only FFN layers 6–11; reproduce that graph with `--ffn-start 6 --attention-output-start 12`. Changing quantization changes vectors: v10 rebuilds semantic embeddings and uses separate persistent cache keys, while preserving source files and the keyword index. See `docs/rwkv-cpu-optimization-20261022.md` for measured speed and retrieval limitations.
