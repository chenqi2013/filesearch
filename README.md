# 本地知搜 MVP

面向 Windows 10/11 的本地文档搜索桌面应用。项目采用 Tauri 2 + React + TypeScript 桌面界面、Rust 外壳，以及可独立运行的 Rust 搜索核心服务。

## 已实现

- 添加、移除一个或多个本地索引目录
- PDF、DOC/DOCX、XLS/XLSX、PPT/PPTX、TXT、MD、CSV、JSON、LOG、RST 文本抽取
- SQLite WAL 文件元数据 + Tantivy BM25 分段倒排索引，可面向 5,000–50,000 个文件
- EmbeddingRWKV Tiny 本地 ONNX Embedding，支持关键词、语义、混合三种检索模式
- 按文件大小和修改时间增量重建，文件变化 900 ms 去抖后后台自动更新
- 文件类型过滤、命中片段、相关度、大小和修改时间
- 打开原文件、在资源管理器中定位文件
- 相同正文结果折叠，详情中保留每份原文件的打开与定位入口
- 索引进度、文档/片段计数、失败文件列表
- 关闭窗口退到系统托盘，索引继续运行；托盘菜单可恢复窗口或退出应用
- 搜索服务异常详情、退出码、诊断日志和限次自动恢复
- 点击文档、片段、失败统计可分页查看明细；文档和片段可直接打开源文件
- 中文、英文、俄文界面
- 索引仅保存在本机应用数据目录，不上传文档

## 快速运行

环境要求：Node.js 20+、pnpm 10+、Rust 1.87+。Windows 需要 WebView2 Runtime 和 Visual Studio C++ Build Tools。

```bash
pnpm install
pnpm desktop:dev
```

`desktop:dev` 会先编译独立搜索服务为 Tauri sidecar，再启动桌面应用。

只运行搜索核心：

```bash
cargo run -p search-core -- --listen 127.0.0.1:47653 --data-dir .filesearch-data
```

只运行 Web 界面：

```bash
pnpm dev
```

Web 开发界面位于 [http://127.0.0.1:1420](http://127.0.0.1:1420)。浏览器模式不能选择或打开本地文件，需要同时启动搜索核心；完整功能请使用 Tauri。

## 构建 Windows 安装包

在 Windows 构建机运行：

```powershell
pnpm install
pnpm desktop:build
```

安装包输出到 `target/release/bundle/`。默认构建 CPU 版，不下载或打入 CUDA/cuDNN 运行库；需要 NVIDIA 可选版时使用 `pnpm desktop:build:cuda`。`scripts/prepare-sidecar.mjs` 会根据当前 Rust target triple 生成 Tauri 所需的 sidecar 文件名。
NSIS 安装器升级前会自动关闭旧版桌面进程和搜索核心，避免运行中的 DLL 导致覆盖失败。

## 后台运行与连接诊断

点击窗口关闭按钮或“退到后台”会隐藏窗口，不会停止索引。单击托盘图标或选择“显示主窗口”可恢复窗口；右键菜单“退出本地知搜（停止索引）”才会结束应用及其启动的搜索服务。电脑休眠、关机后不能继续处理，退到后台也不会改变 Embedding 的计算速度。

连接异常时，索引状态下方可进入“服务连接详情”，查看请求错误、最近一次服务退出码、桌面构建标识、上次收到的文件/步骤信息及日志尾部，并可手动重连、复制诊断信息或打开日志目录。请求超时、连接失败、异常响应与业务错误分别处理；索引中修改目录的 HTTP 409 不代表服务崩溃。

Windows 日志默认保存在 `%LOCALAPPDATA%\com.localfind.desktop\logs\`：`search-core.log` 记录服务输出和文件/阶段变化，`supervisor.log` 记录启动、退出和请求故障。单个日志达到约 10 MiB 时轮转，保留一份 `.previous.log`。日志及复制的信息可能含文件名、完整路径、错误堆栈，发送客户日志前请检查敏感信息。

只有确认本应用启动的服务进程退出，才采用退避方式自动重启；首次启动失败也会有限次重试。连续失败最多自动重试三次，之后由用户手动重试，避免无限崩溃循环。健康接口超时但进程仍在时不会创建第二个服务；启动时发现端口已有健康服务则直接复用，退出应用不终止该外部进程。目录任务、增量事件和重试队列写入 SQLite，服务重启会重新扫描未完成目录并继续队列。未修改文件可复用解析检查点和该文档已持久化的兼容窗口向量，正在计算但尚未保存的一批会重新计算。暂停状态在重启后保留，主动取消的任务不会自动补扫；模型或解析版本不兼容、源文件已修改时需重新处理。

## 数据位置

桌面版把 SQLite、Tantivy 和本地模型缓存放在 Tauri 的应用本地数据目录：

- Windows：`%LOCALAPPDATA%\com.localfind.desktop\`
- macOS：`~/Library/Application Support/com.localfind.desktop/`

其中 `search.db` 保存文件元数据、处理状态、检查点、文档向量和全文窗口向量，`tantivy/` 保存全文倒排索引。Windows 安装版的失败记录位于 `%LOCALAPPDATA%\\com.localfind.desktop\\search.db` 的 `failures` 表中，也可直接在界面点击“失败”查看；开发运行时对应项目目录下的 `.filesearch-data\\search.db`。EmbeddingRWKV Tiny ONNX 模型随 Windows 安装包内置，应用只读取源文件，不会修改、移动或删除源文件。

语义索引使用内置的 `EmbeddingRWKV Tiny` 模型（RWKV7、768 维），采用官方 World 词表、单个 EOS 和 L2 归一化，单次输入最多 1024 tokens（包含 EOS）。正文按 480 字符窗口、400 字符步长完整覆盖，取消每文档 7 个窗口的限制；另外保留有上限的结构摘要向量。文件名作为正文窗口输入前缀，窗口向量均值归一化后作为文档代表向量。当前量化版本与 profile 以 `embedding.rs` 的 `EMBEDDING_PROFILE` 为准。检索以原查询为基础，并按短查询与口语查询条件加入通用查询指令校验；没有领域同义词映射。语义摘要取自实际候选窗口，混合模式采用关键词 0.25、语义 0.75 的 RRF（k=60），再结合词项覆盖、实际片段证据与相关度门槛排序。分数只表示同一次搜索的排序依据，不是准确率或概率。首次切换不兼容 profile 时自动重建向量。推理在本机完成，不上传正文、不联网下载模型；模型不可用时可回退离线词项特征，界面会显示对应后端。

每份文件先写入正文并提交 Tantivy，使关键词检索可用，再每批最多四个语义窗口生成、保存向量并更新进度；不是等待整个目录完成后才发布关键词索引。相同解析正文按 SHA-256 指纹折叠，在结果条数截断前执行，重复正文在融合排名中共享位置；详情保留所有符合当前类型筛选的原文件入口。此处“相同正文”不等于文件二进制相同，图片或排版可能不同，不会删除或移动任何文件。全文窗口会增加首次语义索引时间，未改变的文件仍走增量跳过。

DOCX 解析按 Word XML 结构读取可见文字，跳过域指令并保留域结果、链接文字和段落边界。解析版本升级后会自动重建已添加目录的索引，以更新旧摘要和向量。关键词查询优先使用双字词和英文词，过滤常见问句词；单个汉字查询仍受支持。关键词候选所需命中词数按有效查询词数的 25% 向上取整，最少两个、最多四个（查询只有一个词时命中一个即可），避免长问句被过度过滤；没有合格关键词命中的候选需达到独立语义门槛。界面分数仍为排序分，不是准确率或相关概率。

完全离线环境可在启动前设置 `FILESEARCH_EMBEDDING_OFFLINE=1`，直接使用离线特征。

CPU 安装包仅包含 CPU ONNX Runtime。NVIDIA 可选版额外包含 CUDA 版 ONNX Runtime 和所需运行库，启动时检测驱动和 GPU，失败时回退 CPU。当前 `Rwkv7` 自定义 WKV 算子仍为 CPU 实现，因此可选 CUDA 版本只加速其余 ONNX 节点。

## 大数据量设计

索引状态区可以选择“全速索引”或“日常使用（让出 CPU）”。日常模式减少解析并发，并在向量批次之间让出时间；查询到来时，索引在下一批边界暂停竞争模型。它不改变全文窗口覆盖，也不保证正在执行的单次推理立即停止。

失败列表支持单个、本页和全部重试；空白文件在“已跳过”中单独显示。文件详情可进入完整提取文本的分页预览、相关片段与 PDF 页码／Excel 工作表序号及行号定位。旧索引没有位置元数据时，可点击“重新解析此文件”补充。定位发生在应用内文本预览，打开原文件仍交给系统默认软件。

“更多筛选”支持目录、修改时间、文件大小、文件名／正文范围、完整短语和排除词。结果去重后分页；元数据与文本约束在候选截断前应用。排序基于有限的召回候选集，大目录结果数不是全部可能匹配文件的精确计数。顶栏“诊断与日志”在连接正常时也可打开，并导出逐文件耗时、失败／跳过、索引状态及桌面服务日志尾部；服务断开时保留可用的桌面诊断。

- SQLite 使用 WAL、动态 Token 批处理 Embedding 和批量事务写入；解析与 Embedding 采用有界流水线，最多等待两份已解析结果，解析最多 4 个线程（日常模式最多 2 个）。单个文件仍受 200 MB 上限约束，全文向量会随文本长度增长。
- Tantivy 只保存分段词项与定位 ID，正文和状态由 SQLite 管理，避免 JSON 全量读写。
- 语义层保存每文档代表向量、全部正文窗口（SQLite `semantic_passages`）及有限结构摘要；启动时载入内存并行扫描。长 TXT 的首次索引成本与全文长度相关，恢复时复用已保存的兼容窗口。
- 文件监听自动合并短时间内的批量变化；共享盘断线时保留已有结果，恢复后自动补扫。
- 关键词查询跳过向量读取，单文件增量事件只读取轻量路径映射，避免在 5 万文件规模下反复载入约 146 MB 向量。

运行 50,000 文档 SQLite 容量测试：

```bash
cargo test -p search-core sqlite_wal_handles_fifty_thousand_documents -- --ignored
```

## 当前边界

- `.doc`、`.xls`、`.ppt` 会优先通过 LibreOffice、其次通过本机 Microsoft Office 转换临时副本后解析；原文件不修改。两者均未安装或转换失败时会列入失败文件。
- 扫描版 PDF、图片型 PDF 或不受支持的 PDF 文字编码会自动降级为 Windows OCR；加密 PDF 会明确列为失败文件。
- PDF 和 Office 文档解析采用独立 worker，单文件默认 180 秒超时；超时文件会记录为 `timeout` 失败并继续处理后续文件。
- 已完成 5 万条合成元数据容量测试；上线前仍建议在目标 Windows 机器和真实混合文档/共享盘环境进行长时间压力测试。
