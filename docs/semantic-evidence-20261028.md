# 语义候选过滤修正与回归验证（2026-10-28）

本轮修正应用过滤中丢失证据的问题。固定样本中，语义／混合搜索的正例目标文件命中从 62/68 增至 63/68，未新增负例结果；收益有限，不能据此认为语义搜索问题已全部解决。

## 实际修改

修改范围为 `crates/search-core/src/search.rs`。

1. **使用完整语义窗口检查正文证据。** 之前先将窗口裁成约 260 字符的展示片段，再判断词项覆盖、精确匹配和短概念支持。展示裁剪可能丢掉窗口后面的证据，与该窗口的向量输入不一致。现在这些检查使用完整窗口，语义候选保留完整原文，最后输出时再裁剪展示。
2. **在同一检索请求中保持过滤门槛一致。** 根据原始窗口候选计算一次门槛，窗口筛选和最终候选检查共用；不再根据已经筛选后的文档重新计算。没有正文窗口的旧索引路径仍按原始文档向量候选计算门槛。
3. **统一原查询与通用确认查询的支持判定。** 沿用已有的两次查询向量，以同一窗口的几何平均分判断一致性，避免联合分已经合格，却又被确认查询的单独门槛拒绝。已有原查询分数下限、相对门槛及文字／无文字支持要求继续生效。新增用例验证强原查询搭配极弱确认不能通过。

没有加入领域同义词表、文件名例外或针对某条查询的映射。模型、量化、全文窗口、索引生成和模型输入协议均未修改；没有增加 embedding 调用，不需要重建现有索引。

## 性能与取舍

尝试过在查询时对少量短段落重新计算向量，但本次样本中没有稳定提高标注原句的展示数量，冷查询尾部耗时还接近一秒，因此未保留。按候选领先程度放行低分文档也产生了新增负例，最终版本同样未采用。

最终版本没有额外模型推理。另用保存的修改前可执行文件，在同一轮依次执行旧查询对照：语义查询中位耗时约 48.8 ms → 45.0 ms，混合约 22.4 ms → 22.5 ms。该结果未观察到明显额外耗时，受缓存和机器负载影响，不作为提速承诺。索引 embedding 工作量没有变化。
