# 桌面索引与检索改进（2026-11-09）

## 功能与边界

1. 完整目录任务在扫描前持久化，文件变化和手动重试进入带代数的持久队列。服务异常退出／重启后重新扫描未完成目录，避免漏掉尚未开始解析的文件；新事件不会被旧任务的确认删除。暂停状态跨重启保留，主动取消不会自动恢复该目录任务。
2. 解析结果及其 profile、正文片段 ID 和已完成的向量分别持久化。恢复时仅复用未修改、解析及向量版本兼容的检查点；即使通用缓存被淘汰，也可复用该文档已保存的窗口。尚未持久化的一批需要重算，不承诺指令级恢复。
3. 失败文件可单个、本页、全部重试；“已跳过”单独统计与查看。重试异步排队，不删除源文件；修复原文件后可直接重试。文件详情的重新解析入口可补充旧 PDF 的位置元数据。
4. 保持全文语义覆盖和 RWKV 模型。小文件优先扫描；解析与向量生成通过容量为 2 的结果队列衔接，解析工作线程上限为 4（日常模式为 2）。日常模式在推理批次之间让出时间；查询具有批次边界优先权。长 TXT 首次生成全部向量仍需要时间，日常模式可能延长总索引时间。
5. 搜索增加目录、时间、大小、名称／正文、完整短语、排除词及分页。约束在候选截断前执行，短语检查先还原有重叠的正文片段。固定候选池避免翻页改变检索预算；结果总数是候选池内的去重结果数。正文模式去掉名称的显式词项加分，但历史窗口向量本身仍含名称前缀，不能将其解释为重新训练的纯正文向量。
6. 内容预览按 30 个正文片段翻页，展示最多 3 个相关片段、查询文字高亮及原文位置。PDF 使用真实页序号，Excel 使用工作表序号和行号；表名不在当前元数据中。位置仅用于应用内预览；系统默认软件是否能跳到对应位置不作保证。PDF 页文字无法与最终规范化文本可靠对应时，省略该页位置，避免错误定位。
7. 诊断入口始终可见，可导出 JSON（逐文件各阶段耗时、失败／跳过、进度、日志尾部等）；服务断开时导出已有桌面诊断。解析耗时是并发文件耗时的累加，可能大于任务墙钟时间。保留原有 CSV 文件耗时导出。
8. 默认构建仅打入 CPU 运行库，`pnpm desktop:build:cuda` 构建 NVIDIA 可选版本。CUDA 版本的 WKV 算子仍在 CPU，不承诺全模型 GPU 加速。本次未生成新安装器。
9. 显示“排序分数”，移除百分比表达，并说明不是准确率／置信度。保留固定语义回归集，区分召回／顺序变化与纯数值分数变化。不新增领域同义词映射，也不调整模型或相关度门槛。

## 联测方式

`scripts/verify-desktop-features.py` 使用临时目录和真实 RWKV CPU 推理，创建 46 个输入（42 个小 TXT、一个长 TXT、一个空 TXT、一个损坏 DOCX、一个 Excel）。中途暂停并终止进程，删除通用向量缓存，再启动并恢复，验证原片段 ID、已保存窗口、搜索分页、Excel 第 18 行位置、资源模式，以及修复 DOCX 后的重试。所有操作都在隔离索引中进行，不修改用户索引；除故意修复的 DOCX 外，校验输入 SHA-256 不变。

Tantivy 在 Windows 上曾出现临时“拒绝访问”，错误上下文显示段文件，实际也可能来自创建前更新 `.managed.json` 的原子替换。目录适配器针对 Windows 5／32／33 错误有限退避重试，既覆盖新文件创建也覆盖原子元数据替换；不覆盖既有段文件，不吞掉持久错误。用临时独占文件句柄验证元数据替换恢复，并用真实索引流程回归。

语义评估复用冻结的 13 文档、482 正文窗口、12 结构摘要索引；24 条正例和 12 条负例，三种检索模式分别对比本次修改前后的程序。用例是开发阶段制定的固定样本，不是外部盲测，不能据此声称通用准确率。

## 验证结果

- Rust：118 项通过，5 项原有耗时／环境测试保持忽略；包括独占元数据句柄恢复、队列代数、检查点保留、跨片段完整短语和 PDF 两页位置。
- 前端：6 项接口测试通过；TypeScript 与 Vite 构建通过。
- 真实 CPU 联测：46 个输入，中断前持久化 9 个正文窗口，清空通用缓存并重启后完成 119 个，正文片段 ID 保持一致；完成 42 条分页、Excel 第 18 行预览、资源切换和修复后的重试。
- Edge 界面联测：内容预览、筛选参数、结果翻页、失败本页重试、JSON 诊断导出均通过，检查 1280×800 与 800×620 窗口截图；没有脚本异常。界面联测使用受控接口数据，真实接口由上一项单独验证。
- 冻结样本：36 条查询 × 3 种模式，无目标召回丢失，无负例新增结果，关键词结果顺序不变。语义与混合各命中 22/24 正例、12 个负例中仅 4 个返回空列表，与修改前一致。说明仍有模型误召回／漏召回，不能宣称全部语义问题已解决。一条英文关键词查询分数从 0.67 到 0.75，但文件及顺序不变，因分页采用固定候选预算导致归一化范围变化。评估脚本分别记录顺序与数值变化。
- Windows 桌面程序使用 `pnpm tauri build --no-bundle` 编译验证，本次没有生成安装器。
