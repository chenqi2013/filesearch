# 搜索 P1 优化与复测（2026-09-10）

## 实施内容

- 保留 EmbeddingRWKV Tiny / RWKV7 768 维模型及校正后的 CPU WKV，不更换权重或词表。
- 原先每文档最多 4 个头尾拼接片段，改为最多 16 个连续窗口。窗口 480 字符、步长 400 字符；在正文分段内生成候选窗口，超预算时均匀抽样，包含首尾，文档内相同窗口去重。文件名前缀最多 160 字符，模型仍限制 1024 tokens。不是超大文档逐字全覆盖。
- SQLite 新增 `semantic_passages`，独立存储实际窗口文字和向量，一个原始正文片段可以有多个窗口。查询先选每个文档最佳窗口，再截断候选，避免长文档挤占候选名额；语义摘要来自命中窗口。
- 每批文件先保存正文并提交 Tantivy，再按最多四个窗口一组生成、保存向量。每个窗口批次更新当前文件和耗时；同一阶段更新时重置本次计时起点，避免将已累计耗时再加一遍。整个目录仍是串行索引任务，不是全目录双阶段调度。
- 按解析正文序列生成 SHA-256 指纹，相同正文在融合排名中共享位置，结果截断前折叠。详情展示其他文件并提供打开、定位入口，遵守类型筛选。只折叠结果，不删除文件；图片、排版可能不同。
- 混合模式改为等权 RRF，k=60。关键词通道使用有效 BM25 排名；语义通道使用与语义模式相同的校准相关度，并排除未达到门槛的弱候选。保留文件名加分和 P0 过滤规则，显示分数不是相关概率。
- 索引 profile 更新为 `rwkv7-tiny-contiguous-passages-v5`。首次启动自动重建旧向量；未完成代表向量的文件下次启动会重新处理。原文件、目录配置不变。

## 方法与语料

使用独立服务和索引副本，未移除用户桌面端新增的目录。原有 176 份文档的 ID、路径、大小、修改时间和解析正文均核对一致：1,287 个正文片段，9 个既有失败文件。重新插入后的片段 ID 变化，因此更新语料指纹，保留全部查询和相关文档标签。

原 390 个片段向量改为 998 个窗口向量。176 份文档有 145 个不同正文指纹、31 组重复正文。测试脚本将代表文件或 `duplicates` 中任一已标注文档计为命中；以结果组为单位计算 Hit@K，不是逐文件 Precision@K。

原有 36 条正向查询和 4 条领域外查询，加测原有 6 条正向、4 条领域外查询。初版使用原始余弦排名做 RRF，在补充的微服务表格查询中将目标从第 1 降至第 7；对齐语义模式已有校准后恢复。未修改答案标签。这些查询已用于开发回归，不是独立盲测，不能推广为普遍准确率。

## 索引成本与边界

本机 CPU 对独立语料完整重建一次：总计 289.789 秒，Embedding 270.554 秒，解析累计 15.126 秒，SQLite 1.823 秒，Tantivy 2.193 秒。并行解析累计值不一定与墙钟时间严格相加。此次记录来自首次 P1 重建，后续只修订排序和进度显示，没有再次计算窗口向量。

窗口向量数从 390 增至 998，覆盖收益伴随更高首次推理成本；本轮不是 Embedding 加速优化。P0 最终快照的累计索引计时为零（服务重启后），缺少同条件完整计时，不能给出严谨的索引速度倍率。未改变的文件仍增量跳过。

本轮未接入 GPU WKV、HNSW、重排模型、OCR 或全正文无限向量化。CUDA 环境仍只加速 ONNX 中非 WKV 节点。
