# 搜索相关性优化与完整语料回归（2026-10-27）

## 范围

保持现有 RWKV 模型、全文语义窗口和 v10 向量协议，不新增领域同义词表。本轮只调整查询与排序，不重新生成文档向量，不修改用户正在使用的索引，也未替换正在运行的桌面程序或打包安装器。

## 原因与修改

1. 中文短查询原先只要所有字分散出现在片段里，就能得到完整短词支持。现在完整短语须连续出现；双字概念可通过同一正文中的字词和额外语义确认保留，例如“赔款”与“付款／赔偿”，不直接视作关键词精确匹配。
2. BM25 会归一化，弱词命中也可能得到 1.0；原先低可信关键词还能使本不达标的语义分生效。现在正文、结构、精确词项回退各自校验后取分，不互相借用未通过的分数。混合搜索也不让分散泛词单独兜底；纯关键词模式行为不变。
3. 用原模型额外编码通用确认句“关于{查询}的资料”，只验证原查询命中的同一语义窗口，不能用文档另一处内容凑证据。该确认不是生成同义词，也不新增索引向量。
4. 结构证据通过局部正文校验后小幅加分；文档代表向量只作排序加分，不作过滤条件，避免屏蔽长文档深处的真实内容。仅含“页码、行号、内容”等导航字段的表头不再作为主题证据，现有索引无需重建。
5. 精确词项回退保存独立的分数和原始片段，不再把不同片段的最大覆盖率、最高 BM25 和语义摘要混用。保留 ASCII 前缀匹配与重复文档折叠。

这些仍是启发式相关度规则，不等价于语言模型精排器或真实概率，需要持续扩充回归语料。

## 实测方法

对用户索引作只读 SQLite 快照，分别启动旧、新核心的隔离服务，删除的只是测试副本中的监听目录配置，防止扫描原目录。使用同一 RWKV 模型和同一批既有向量，不重建全文 Embedding。

- 14 份原始文档，包括 7 MB 小说全文；不是上一轮的 64 段小说采样。
- 6,049 条正文向量，其中小说 5,567 条；44 条结构向量；6,093 条持久缓存。
- 57 条查询，每条分别运行语义、混合、关键词模式，合计每版本 171 次。
- 其中 39 条明确指定目标文档，包含“榜单”这一已知失败项，而非只统计成功查询。其余查询用于检查误召回或观察歧义，不宣称所有结果均已人工判定。
- 比较查询前后的文档、正文向量、结构向量及持久缓存完整内容指纹：两版本均未改变。
- JSON 与服务日志：`.codex-tmp/ranking-20261027/run5/result.json`。

## 性能与验证

本机 CPU、模型已加载后的单轮串行测量：语义查询中位数约 22 → 42 ms，混合约 6 → 13 ms；语义最大约 65 ms。每个查询先测语义再测混合，后者会复用模型内存缓存，因此不能把两种模式的耗时直接横向比较。调度与负载也有波动，不能据此承诺所有用户设备相同延迟。

额外代价是查询时一次短文本推理；不增加首次索引 Embedding 工作量，不使已有向量缓存失效，不降低全文覆盖。

- Rust 常规测试：84 通过，5 项显式慢／模型测试默认跳过。
- 两项已有客户语义模型回归另行通过，包括合同、办公室岗位、电影和老歌合成案例，以及使用生产输入形态的 PDF 合同。它们不替代客户原文件验收。
- 新单测覆盖：分散字词与连续短语、ASCII 前缀边界、弱关键词／结构不得借用未支持的正文高分、双字概念确认、同一窗口确认与深层片段选择、导航型表头排除。
- release 核心构建通过。

## 仍未解决

- 单独搜“榜单”仍未召回 QS 大学表格，且仍有一份需求评估文档的低分语义误召回。没有通过特例词典或无条件放宽阈值掩盖此问题。
- 39 条明确目标查询只覆盖少量场景；不能保证任意换词、口语问法或新领域都能召回，也不能保证全部次要结果正确。
- 纯关键词模式按原词项规则工作，不承担“钱款→货款”等语义转换；统计中的语义查询不能当作关键词模式缺陷。

## 复现

先保留不同版本的核心可执行文件，准备可读的原始索引；输出目录必须是新的目录。

```powershell
python -B scripts/verify-search-ranking.py `
  --database '<原始索引目录>\search.db' `
  --baseline-executable '<优化前>\search-core.exe' `
  --executable 'target\release\search-core.exe' `
  --output '.codex-tmp\search-ranking-new'
```

脚本会验证既有目标不丢失、排行榜的相关排序与无关结果过滤、小说真实词项保留、显卡驱动负例、关键词一致性、类型筛选、CPU 模型状态，以及全部既有向量与持久缓存不被查询修改。
