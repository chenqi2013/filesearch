# 技术架构

## 模块

```text
React UI
  │ HTTP 127.0.0.1:47653
  ▼
search-core（独立 Rust 进程）
  ├─ notify 文件监听、900 ms 去抖、后台增量队列
  ├─ PDF / Office / 纯文本解析与异常分类
  ├─ EmbeddingRWKV Tiny 本地 ONNX Embedding（按 Token 长度动态组批，WKV 运行时选择 AVX2/FMA）
  ├─ SQLite WAL：目录、文档、正文分段、向量、失败状态
  └─ Tantivy：中文单字/双字词项、BM25 分段倒排索引

Tauri Rust 外壳
  ├─ 启停 search-core sidecar
  ├─ 系统目录选择器
  └─ 打开文件 / 文件夹 / 在资源管理器中定位
```

React 不直接读取磁盘，搜索核心不依赖 Tauri。服务只监听 `127.0.0.1`，跨域来源限制为 Tauri 和本地开发地址。

## 桌面生命周期与服务诊断

关闭主窗口只隐藏到托盘，索引继续在独立进程运行；托盘支持恢复窗口、打开日志目录与退出应用。真正退出时仅结束本应用创建的搜索服务，借用端口上已有的健康服务时不接管其生命周期。

桌面外壳每两秒检查所拥有子进程的退出状态，记录 PID、时间、退出码与系统异常码含义。确认退出后按退避间隔最多重试三次；首次启动失败也有限次重试，停止重试后可手动恢复。进程持续稳定运行超过重试观察窗口后，后续退出重新计算重试预算。接口超时或端口返回非搜索服务响应时不会贸然创建第二个进程。自动重启不保证恢复完整扫描位置，未写入记录的文件可能需要重新发起索引。

前端状态轮询有 5 秒超时且不重叠，普通请求默认 15 秒、搜索 120 秒，区分网络失败、超时、无效 JSON 与 HTTP 业务错误。详情保留最近请求的文件/阶段快照；这些信息来自最后一次成功状态响应，不视为崩溃的确定发生位置。服务日志额外在文件或阶段变化时输出进度，不为每个语义窗口打印日志。

`logs/search-core.log` 捕获 stdout/stderr，`logs/supervisor.log` 记录进程生命周期与节流后的请求错误，两者均按约 10 MiB 轮转并保留上一份。退出码未知时只报告未知，不把内存访问异常误报为内存不足。日志和复制的诊断信息含本机路径，应由用户检查后再分享。详见 [后台运行与连接诊断](../README.md#后台运行与连接诊断)。

## 索引与存储

1. UI 将完整目录列表提交到 `POST /index`，核心递归扫描受支持文件且不跟随符号链接。
2. SQLite 使用文件大小和修改时间识别未变化文件；新增或变化文件由最多 4 个工作线程并行抽取文本，并执行约 800 字符分段。
3. 每批先将正文写入 SQLite 并提交 Tantivy，关键词索引立即可见，再生成语义向量。正文片段按 480 字符窗口、400 字符步长拆分；TXT 先去除正文分段的重叠、还原连续全文，再直接生成语义窗口，避免两层分段产生额外重叠。所有非空窗口都生成语义向量；完全重复的窗口去重，不拼接远距离文字。以文件名前缀加窗口文本生成 EmbeddingRWKV Tiny 768 维向量，单条最多 1,024 Token（含 EOS），按相同 Token 长度合批，每批最多四个窗口、2,048 Token，逐批写入 `semantic_passages`、更新窗口进度并检查暂停/取消。窗口均值归一化后作为文档代表向量。模型采用官方 World 词表与单个 EOS，FFN 第 3–11 层和注意力输出投影第 6–11 层的大矩阵使用 per-channel 动态 INT8（层号从 0 开始），其他路径保持 FP32；仅相同 Token 长度的文本组批，避免 padding 污染循环状态。x86-64 CPU 的 WKV 运行时优先使用 AVX2+FMA，缺少 FMA 时回退到 AVX2，非 AVX2 设备回退标量实现。中途关闭时，没有完成代表向量的文档下次启动会重新处理，但通过独立的 `passage_vector_cache` 复用已完成窗口，只推理未命中的内容。缓存键为模型配置版本及完整输入（包括文件名）的 SHA-256，不保存原文；文件完成后保留最多 100,000 条，模型降级向量不写入缓存。

   2026-10-22 的 CPU 量化调整使用 v10 向量协议。由 v9 升级后，下次启动会自动重建已有文档的语义向量；关键词索引和源文件保留。v9 缓存不能用于 v10，防止查询向量与正文向量使用不同量化配置。耗时、检索排名波动和测试范围见 [CPU 优化实测](rwkv-cpu-optimization-20261022.md)。

   2026-10-26 增加结构辅助向量：自动提取章节标题与表格字段，去编号、去重，过滤分段边缘的残缺行与过短标题，每文档最多额外 32 条、每条最多 80 字符。辅助输入不加文件名，独立写入 `semantic_anchors` 并关联原正文分段，不混入正文均值；全文正文窗口仍全部保留。两类向量共用原有持久缓存与合批流程。PDF 只修复检测到的单汉字字距，保留换行、英文词间空格和原始宽间隔／制表符边界。抽取协议升级会重新处理未修改文件，相同模型及完整输入对应的 v10 缓存仍可复用，不使模型缓存整体失效。详见 [真实文件召回回归](semantic-structure-20261026.md)。
4. Tantivy 保存片段级 BM25 索引。中文预处理包含单字、相邻双字及英文词，文件名词项重复加权。SQLite 按解析正文片段序列保存 SHA-256 指纹，用于相同正文折叠；不等同于文件二进制去重。
5. SQLite 使用 WAL 与外键级联；Tantivy 提交后刷新 reader。服务启动时会比较 SQLite 片段数与 Tantivy 文档数，不一致则从 SQLite 自动重建全文索引。
6. 旧版 `index.json` 首次启动自动迁移，随后后台重新扫描以补齐 EmbeddingRWKV Tiny 向量。

旧版 `.doc/.xls/.ppt` 文件会先在系统临时目录转换为 OOXML 副本：优先调用 LibreOffice，无可用 LibreOffice 时在 Windows 上调用本机 Microsoft Office。转换完成后复用现有 OOXML 提取器，临时副本随即删除，用户原文件不会被修改。

目录暂时不可访问或共享盘断线时，该根目录标记为 `offline`，不会删除已经建立的索引。明确从 UI 移除目录时才删除对应记录。

## 检索策略

- 关键词：Tantivy BM25 召回片段，最多保留 1,000 个候选并按文档去重。
- 语义：本地 EmbeddingRWKV Tiny 分别编码原查询与通用确认句“关于{查询}的资料”，与常驻内存的片段向量比较。查询时每个候选文档保留最多八个高相似窗口，并补充 BM25 命中分段关联的窗口，再逐窗口校验和选择，不再提前压成一个最高原查询向量窗口。这只是查询候选数量，不是全文向量保存上限。原查询与确认句必须在同一窗口形成证据；联合相似度可支持口语改写，无局部词项重合时采用更严格的联合门槛。双字概念保留带语义确认的局部字词支持。正文、结构、精确词项回退分别校验；词项回退可使用同一窗口的词项集中度及双查询相似度确认，不能借文档另一处的高分。文档代表向量仅小幅加分，不过滤长文档深层内容。结构通道仍要求标题／表头与同一原始分段中的正文双重证据，并排除纯导航字段。文档召回通过后，摘要在该文档的候选正文窗口中按双查询联合相似度和 IDF 词项覆盖选择，再截取局部匹配密集的文本；不强制展示结构通道的表头或首段。英文摘要支持简单复数标签匹配，但不改变关键词召回词项。上述规则仍不能保证找到答案所在片段。无领域同义词表，无新增查询推理，全文向量和索引协议不变。历史结果见 [相关性优化实测](search-ranking-20261027.md)，本次修正见 [片段定位与过滤回归](semantic-window-ranking-20261027.md)。
- 混合：两路排名采用加权 RRF，排序分为 `0.25 × 61/(60+关键词排名) + 0.75 × 61/(60+语义排名) + 文件名加权`，未命中的通道贡献为零。关键词通道使用通过精确性检查的片段分数，纯关键词模式仍保持原 BM25 逻辑；不再仅凭分散泛词进入混合结果。相同正文共享各通道排名，最终排序后、截断前折叠；`duplicates` 返回符合当前类型筛选的其他原文件。摘要来自排名较好通道的实际命中文本。

这种结构为文档中的所有非重复窗口保存语义向量，长文档不再抽样，因此每个正文位置都参与语义召回。服务启动时加载向量并在增量索引后同步更新，Tantivy 负责精确词项定位。关键词模式不扫描向量，普通文件事件也只读取轻量路径映射。完整覆盖会随正文长度线性增加索引时间、存储和语义候选计算量；若后续扩展到数十万或百万文件，可把语义层替换为 HNSW，而无需改变 UI/API。

## 实时增量更新

- `notify` 对全部索引根目录递归监听，事件经过 900 ms 去抖和路径去重。
- 全量索引和增量索引共享一个串行任务门；全量任务期间发生的事件进入待处理集合，完成后继续消费，避免并发写 SQLite/Tantivy。
- 文件创建/修改会重新抽取并替换对应 Tantivy 文档；文件或目录删除会级联移除对应记录。
- 每 30 秒检查根目录可达性；断线写入失败记录，恢复后触发补扫并重新建立操作系统监听。

## 异常分类

失败记录包含 `encrypted`、`permission`、`offline`、`corrupt`、`parse` 或 `internal` 分类。加密 PDF 在解析前检查 `/Encrypt` 标记；损坏 OOXML、权限不足和目录断线不会中止其他文件的索引。

## 本地接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 服务、存储和 Embedding 状态 |
| GET | `/stats` | 索引进度、后端、模型与监听状态 |
| POST | `/index` | 提交完整目录列表并开始增量全扫 |
| POST | `/search` | 关键词、语义或混合搜索 |
| GET | `/failures` | 分类后的失败文件列表 |
