# 技术架构

## 模块

```text
React UI
  │ HTTP 127.0.0.1:47653
  ▼
search-core（独立 Rust 进程）
  ├─ 目录扫描与增量判断
  ├─ PDF / OOXML / 纯文本解析
  ├─ 分段、词项与本地特征向量
  ├─ 关键词 / 语义 / 混合排序
  └─ index.json 持久化

Tauri Rust 外壳
  ├─ 启停 search-core sidecar
  ├─ 系统目录选择器
  └─ 打开文件 / 在资源管理器中定位
```

React 不直接读取磁盘，搜索核心不依赖 Tauri。后续可以把桌面 UI 换成 Web 管理台，或把搜索核心部署成受控的本地服务，而不改动索引协议。

## 索引流程

1. UI 将目录列表提交到 `POST /index`。
2. 核心递归扫描受支持文件，不跟随符号链接。
3. 文件大小和修改时间未变化时复用已有记录。
4. 解析出的文本以约 800 字符、100 字符重叠进行分段。
5. 每个片段预计算排序词项和 256 维本地特征向量。
6. 新索引先写临时文件，再原子替换 `index.json`。

移除目录也会触发一次增量重建；移除最后一个目录会清空索引记录。

## 检索策略

- 关键词：查询词项覆盖率，文件名完整包含时增加权重。
- 语义：查询与片段特征向量的余弦相似度。
- 混合：`0.68 × 关键词 + 0.32 × 语义 + 文件名加权`。

API 返回每个文件的最佳片段，并按分数降序排列。Embedding 计算集中在 `crates/search-core/src/search.rs`，便于后续替换为 ONNX、fastembed 或企业内部模型。

## 本地接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/health` | 服务存活检查 |
| GET | `/stats` | 索引状态与进度 |
| POST | `/index` | 提交完整目录列表并开始增量索引 |
| POST | `/search` | 搜索与过滤 |
| GET | `/failures` | 最近一次索引失败列表 |

服务只监听 `127.0.0.1`。浏览器跨域访问仅允许 Tauri 生产来源和本项目本地开发地址。

## 生产化建议

- 用 SQLite 保存文件元数据和任务状态，用 Tantivy 保存 BM25 倒排索引。
- 接入本地多语言 Embedding 模型及 HNSW 向量索引。
- 使用文件系统 watcher 合并短时间内的变更事件。
- 为索引文件增加操作系统密钥库保护、可选加密和迁移工具。
- 增加旧 Office 格式转换、OCR、权限继承和共享盘断线恢复。
