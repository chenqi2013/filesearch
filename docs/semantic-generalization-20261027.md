# 独立换词与口语查询评测（2026-10-27）

## 结论

当前版本确实具有超出关键词匹配的语义召回能力，但不能认为已经解决任意换词搜索问题。本次新拟的 68 条正例中，语义和混合搜索均有 55 条目标文件排第一，57 条进入前十，11 条未召回目标文件。部分命中文件的展示片段与查询无关，文件级命中不能等同于内容定位正确。

上一轮熟悉查询上的高命中率不能代表泛化效果。本轮没有根据失败项修改算法或阈值，也没有重新打包、重启用户桌面应用或重新生成 embedding。

## 样本和方法

- 使用当前真实索引的只读快照：14 份文档、3,443 个检索片段、6,049 个正文语义向量、44 个结构锚点；包含完整小说，未缩减长文窗口。
- 根据实际索引正文人工新拟 68 条正例，每条预先固定目标文件和证据原句，并在运行前确认原句存在。它们不是收集到的客户独立真实查询，也未用于本轮调参。
- 68 条新查询与上一轮评测查询不重叠，完整查询句子均未出现在目标正文；这不代表完全无词项重叠，因此同时运行关键词对照。
- 另有 12 条无直接答案负例、8 条歧义查询和 9 条旧控制查询，共 97 条查询、三种模式、291 次请求。歧义查询不计准确率。
- 使用当前已发布桌面版对应的 search-core 和内置 RWKV Tiny CPU 模型。复制 SQLite 后仅清空测试副本的目录配置，避免扫描或修改源文件；测试服务使用独立端口。
- 查询顺序固定种子随机化，轮换三种模式的先后顺序；测试前预热。测试完成后停止独立测试服务。
- 源数据库及测试副本的文档/向量/cache 指纹测试前后一致，未改变现有索引。

## 已核实的问题

### 目标文件漏召回（11 条）

| 查询 | 预期内容 |
|---|---|
| 出了纠纷去哪个法院 | 合同中的当地方法院诉讼条款 |
| 交货少了应该怎么补 | 合同中的补送不足数量 |
| 送过来的东西坏了谁掏钱 | 合同中的供方负责赔偿；实际返回小说战斗片段 |
| 货不对板能不能退回去 | 合同中的退换货条款 |
| 月结对账需要哪些凭据 | 合同中的入库单、对帐单 |
| 文件内容会不会被发到网上 | 软件需求中的不上传文档正文 |
| 断网以后还能找电脑里的资料吗 | 软件需求中的离线运行 |
| 电脑突然断电后还要从头处理吗 | 软件需求中的断电后可继续任务 |
| can I add annotations on a phone | 英文说明中的手机不支持该批注功能 |
| 手机上一次显示一页并左右滑动翻页 | 英文说明中的 Single Page 和 swipe gesture |
| 自动识别文件类型并提取元数据的工具 | 英文 Tika 说明；实际返回的中文需求文档也有相关内容，不能全部判为误召回 |

其中“月结对账需要哪些凭据”“文件内容会不会被发到网上”“can I add annotations on a phone”三条，关键词模式能找到目标，语义和混合模式反而没有结果。需要专项诊断候选召回和后续过滤，不能仅把问题归因于 embedding 模型，也不能在未诊断前直接放宽所有门槛。

自动检查中，57 条目标命中结果里有 30 条展示片段包含预先固定的证据原句。这个数字不是片段准确率：没有原句也可能存在其他相关表述，或原句被截断。上述具体问题以人工核对为准。

### 无答案时的误召回

12 条负例中，语义/混合均有 9 条返回空结果，以下 3 条返回了不能直接支持请求的内容：

- “Linux服务器磁盘扩容操作手册”：返回需求文档中的硬件配置、共享盘权限。
- “劳动仲裁申请书模板和填写要求”：返回供应商合同中的送货单填写。
- “Python虚拟环境依赖冲突排查教程”：返回 Python 运行时选型或验收交付内容。

这说明仍可能因少量相关词或主题相近返回无用文件。9/12 是本负例集合的空结果比例，不能当作总体精确率。关键词模式也有 3 条负例返回结果，但具体查询并不完全相同。

## 查询耗时与限制

| 模式 | 本机单轮中位数 | P95 |
|---|---:|---:|
| 语义 | 77 ms | 141 ms |
| 混合 | 37 ms | 140 ms |
| 关键词 | 33 ms | 46 ms |

这些数字来自已预热、同一进程、有查询缓存的单轮测试。虽然轮换了模式先后，仍不能据此断言混合比语义更快；也不能与不同长度查询、不同缓存状态的上一轮直接比较。这是查询耗时，不是文档建索引 embedding 耗时。

样本库只有 14 份文件，查询由阅读现有内容后拟定，并非独立客户验收集；领域覆盖、目标标注和样本数量都有局限。本轮数字仅描述该固定测试集，不代表产品通用准确率。

## 建议的后续顺序（本轮未实施）

1. 优先诊断并修正“正确文件、错误片段”：记录各候选窗口及最终摘要来源，确保最终展示片段有足够查询相关性；不能只看文件级分数。
2. 对关键词可命中、语义/混合却丢失的三条做候选与过滤链路诊断，区分模型相似度不足和策略误过滤。
3. 专项测试口语改写、否定句、跨语言查询；保留无答案负例约束，避免通过全局降低阈值换召回。
4. 保持现有 RWKV 模型和全文窗口，优先评估查询侧候选选择与片段重排。是否需要重新索引、增加查询耗时，须由实现与实测确认，不预先保证。
5. 本轮样本保留为回归集；后续调参后另收集未见过的客户查询验收，避免只在已有失败句上提高分数。不采用手工领域同义词表。
