# RWKV 与 Qwen 语义检索对照（2026-10-29）

本次实测中，Qwen3-Embedding-0.6B 在部分跨语言查询和具体证据段落定位上优于 RWKV Tiny；目标文件第一名的总体差距很小，且两者在否定、数值条件和没有直接答案的查询上都存在错误。当前 RWKV 的 CPU 部署生成向量更快。不能把这些结果概括成“换成 Qwen 就能解决所有语义搜索问题”。

本轮只增加对照脚本、冻结用例和报告，没有修改生产检索代码、替换桌面模型、重建用户索引或更新安装包。

## 模型及核对

同时测了四条路径，每条都运行原查询和通用检索指令查询，避免将某个导出版本的行为当作整个模型的能力。

| 路径 | 模型／精度 | 运行方式 | 维度 |
|---|---|---|---:|
| RWKV 当前部署 | EmbeddingRWKV Tiny，现有混合 INT8 | Rust WKV + ONNX Runtime 1.22.0，CPU | 768 |
| RWKV 参考 | 官方 Tiny 原权重，FP32 | 官方 C 推理，CPU | 768 |
| Qwen 本地部署 | Qwen3-Embedding-0.6B，本地 INT8 ONNX 导出 | ONNX Runtime 1.29.0，CPU | 1024 |
| Qwen 参考 | 官方 Qwen3-Embedding-0.6B 原权重转 FP32 执行 | PyTorch 2.6.0 + Transformers 5.3.0，CPU SDPA | 1024 |

Qwen 原权重来自官方仓库 `Qwen/Qwen3-Embedding-0.6B`，固定版本 `97b0c614be4d77ee51c0cef4e5f07c00f9eb65b3`；权重 SHA-256 为 `0437e45c94563b09e13cb7a64478fc406947a93cb34a7e05870fc8dcd48e23fd`，与官方 LFS 信息一致。原始检查点存储为 BF16，本轮在 CPU 上以 FP32 运算；不运行远程自定义代码。

Qwen 参考实现复现官方 README 的两查询／两文档例子，相似度最大绝对误差为 **5.36e-7**。本地 INT8 导出在相同例子中的最大差为 **0.1031**。这说明有必要单独比较参考模型，不能只看本地 INT8。

RWKV 官方源码固定版本为 `3c306736c58550f4be6d384be068512ba9bfbd72`。沿用前一轮已经核对权重、分词及 FP32 推理数值的官方 C 路径，单 EOS、RETR 输出头，不修改官方推理源码。其具体核对见 [官方 RWKV 对照报告](official-rwkv-comparison-20261028.md)。

## 统一输入和检索方法

- **现有资料集**：固定索引中的 13 份非小说资料，完整保留其 482 个正文语义窗口，包含 PDF、Word、Excel、TXT／日志和旧 Office 示例。原来 5,567 窗口的小说在两边都排除，没有抽样后作为完整小说评估。这一选择在推理前冻结，结论不覆盖整本小说检索。
- **新构造资料集**：36 份独立对照文本、36 个窗口。包括客户此前反馈的五类场景，以及相近干扰文本：充电宝／充电桩、办公室／野外岗位、家庭动画／恐怖片、老歌／新歌、300／500 元、30／60 天、待审批／已通过、自动续约／不自动续约、离线／云端等。文件名统一为无含义的 `sample-sXX.txt`。
- **查询**：现有资料 100 条有目标查询、28 条无直接答案查询；新资料 58 条有目标查询、10 条无直接答案查询，总计 **196 条**。现有资料分为 70 正例＋12 负例的校准部分和 30 正例＋16 负例的留出部分。
- 所有用例、目标文件和标注原句都在本轮模型推理前冻结。没有看完结果再改标注、添加领域同义词或给失败查询写例外。
- 两边输入完全相同的文件名前缀、换行和正文窗口；分别按各自 tokenizer 编码。RWKV 参考正文最长 495 token，Qwen 最长 373 token，全部低于共同的 1,024 token 检查上限，没有因为截断丢掉证据。本轮没有测试 Qwen 的更长上下文优势。
- 查询分别测试原文和通用指令 `Instruct: Given a query, retrieve documents that answer the query\nQuery: {query}`。这是一句通用任务说明，不是“赔款→违约金”这样的词映射。Qwen 文档不加查询指令，按最后有效 token pooling；RWKV 用单个 EOS pooling。输出均 L2 归一化。
- 主对照只做向量余弦排序。每份文档取其最高窗口分，按文档去重。**不加入 BM25、结构锚点、重排器或生产过滤门槛**，以隔离模型表示的影响。

所有检索在只读源快照及独立副本上执行。源数据库的文档、正文向量、锚点和持久向量缓存指纹保持不变。

这些是开发者编写的测试，很多现有查询已参与此前分析；新查询也由开发者编写，并非客户盲测。指定原句未穷尽所有相关段落。以下数字不能当作真实用户总体准确率。

## 参考模型：找对文件和找对段落

下表均使用通用检索指令，不施加无答案过滤。“标注段落”指包含预先标注原句的窗口，在全体候选窗口中的排名，不代表完整片段准确率。

| 指标 | RWKV 官方 FP32 | Qwen 官方权重 FP32 |
|---|---:|---:|
| 现有资料 100 条：目标文件第一 | 93/100 | 94/100 |
| 现有资料 100 条：目标文件前三 | 98/100 | 100/100 |
| 现有资料 100 条：标注段落第一 | 55/100 | 66/100 |
| 现有资料 100 条：标注段落前三 | 75/100 | 86/100 |
| 新构造 58 条：目标文件第一 | 50/58 | 51/58 |
| 新构造 58 条：目标文件前三 | 55/58 | 58/58 |

两个资料集的目标文件第一名只各差一条。查询级配对检查中，现有资料为 Qwen 单独答对 5 条、RWKV 单独答对 4 条；构造资料为 4 条和 3 条。描述性查询重采样的差值区间覆盖零，且同文档查询彼此相关，不能据此宣称 Qwen 的总体文件检索能力显著优于 RWKV。

更明确的差异在段落定位。例如现有合同资料中，32 条查询的目标文件第一两边都是 31 条，而标注段落第一为 **RWKV 11/32、Qwen 19/32**。

| 现有资料查询 | RWKV 标注窗口排名 | Qwen 标注窗口排名 | 说明 |
|---|---:|---:|---|
| 出了纠纷去哪个法院 | 19 | 1 | 两边目标文件都是第一，Qwen 更好定位诉讼条款 |
| 送过来的东西坏了谁掏钱 | 4 | 1 | 两边文件第一，Qwen 更好定位赔偿原句 |
| 月结对账需要哪些凭据 | 30 | 2 | RWKV 目标文件第四，Qwen 第一 |
| 交货少了应该怎么补 | 6 | 15 | 这一条 RWKV 的标注段落位置更好 |
| 货不对板能不能退回去 | 1 | 2 | 两边均找到目标，RWKV 标注段落更靠前 |

## 不同场景的实际例子

以下来自新构造资料，表格数字为目标文档排名，比较官方 FP32 参考路径，不代表客户原始文件的端到端测试。

| 查询 | RWKV | Qwen | 观察 |
|---|---:|---:|---|
| 赔款 | 1 | 1 | 均找到赔偿／违约条款 |
| 充电宝 | 1 | 1 | 均区分便携电源与汽车充电桩 |
| 坐办公室的岗位 | 1 | 1 | 均找到办公室招录岗位 |
| 适合全家一起看的轻松片子 | 1 | 1 | 均找到家庭动画喜剧 |
| 以前很火的老歌 | 1 | 1 | 均找到经典怀旧歌单 |
| 怎样左右划一下翻到下一页 | 6 | 1 | 中文查询对应英文 PDF 功能，Qwen 更好 |
| 自动识别文件格式并抽取元数据的工具 | 6 | 1 | Qwen 找到英文 Tika，RWKV 更偏向 OCR |
| 不用经常往山里跑的公务员工作 | 2 | 2 | 两边都把野外岗位排第一，忽略了否定约束 |
| 哪个标准住宿上限是五百而不是三百 | 2 | 2 | 两边都把 300 元标准排第一 |
| 已经审核通过可以马上买的采购申请 | 1 | 2 | Qwen 把待审核申请排第一，RWKV 正确 |
| 要继续合作必须再签新合同的规定 | 1 | 2 | RWKV 正确，Qwen 把自动续约合同排第一 |

新构造的跨语言组为 RWKV **3/6** 第一、Qwen **6/6** 第一；否定组为 **6/6 对 4/6**，数值组为 **5/6 对 4/6**。每组样本很少，说明本轮具体优劣，不构成通用模型排名。

这五类客户场景里的基础问题，两种模型在构造文本中都可命中。但 PDF 图片文字没有抽出、表格解析丢行、向量没有保存、应用过滤丢掉候选，仍然会导致实际软件搜不到；本轮绕过解析，不证明最初五份原始文件已经没有问题。

完整的 158 条有目标查询及 38 条无直接答案查询见 [逐条结果](rwkv-qwen-cases-20261029.md)。

## 量化部署和查询方式的影响

| 路径 | 现有资料：目标第一／100 | 标注段落第一／100 | 新构造：目标第一／58 |
|---|---:|---:|---:|
| RWKV 当前混合 INT8，原查询 | 91 | 50 | 47 |
| RWKV 当前混合 INT8，加指令 | 93 | 54 | 49 |
| RWKV 官方 FP32，原查询 | 91 | 50 | 48 |
| RWKV 官方 FP32，加指令 | 93 | 55 | 50 |
| Qwen 本地 INT8，原查询 | 89 | 59 | 46 |
| Qwen 本地 INT8，加指令 | 93 | 64 | 48 |
| Qwen 官方权重 FP32，原查询 | 89 | 60 | 48 |
| Qwen 官方权重 FP32，加指令 | 94 | 66 | 51 |

RWKV 当前向量与官方 FP32 在 482 个正文窗口中的向量余弦中位数约 **0.99818**，最低 **0.99484**；现有 100 条查询的目标文件排名未因本轮去量化而改变，但少数构造案例有变化。

Qwen 本地 INT8 导出与官方 FP32 的正文向量余弦中位数约 **0.82619**，最低 **0.72655**；加指令查询向量的中位数约 **0.86283**。两个 Qwen 路径使用相同 tokenizer 文件，官方参考已复现官方示例。本轮能确认这两条部署路径存在明显差异，**没有进一步隔离是量化策略、导出过程还是 ONNX 执行造成**，不能笼统说所有 Qwen INT8 都有这些损失。

例如构造查询“赔款”在本地 Qwen INT8 中目标第二、差旅标准第一，而官方 FP32 中赔偿条款第一。若以后评估 Qwen 部署，应先验证导出保真，不能直接把旧 INT8 文件的结果作为模型能力上限。

## 无答案和过滤

原始向量排序对无答案查询也会产生第一名，不能将其当作模型会拒答，也不能把“总能返回结果”算成搜索准确。

本轮另在现有资料的 70 正例＋12 负例中，为各模型独立选择最高分阈值，以平衡可回答与不可回答查询；**没有使用留出或构造用例调整阈值**，也没有共用两个模型的数值门槛。这只是诊断，未接入应用。

| 留出查询：30 正例＋16 负例 | RWKV 官方 FP32＋指令 | Qwen 官方 FP32＋指令 |
|---|---:|---:|
| 无过滤时目标第一 | 30/30 | 28/30 |
| 校准阈值后仍保留目标 | 29/30 | 30/30 |
| 校准阈值拒绝无答案查询 | 7/16 | 7/16 |

仍有 9/16 无答案查询会得到过阈值结果。新构造的 10 条负例中，该阈值分别拒绝 3 条和 4 条。两种模型都不能靠一个最高分阈值稳定区分“主题相关”和“确实有答案”。

还单独运行当前应用核心，在相同 13 份资料上得到：100 条正例目标第一 **92/100**、前三 **95/100**，28 条负例为空 **15/28**。这是包含关键词回退、结构锚点、多查询支持和门槛的最终软件结果；与上面纯向量算法不同，不能直接作为同算法模型优劣表。过滤仍可能丢掉原本存在的候选，问题不能全部归因于模型。

## CPU 成本

本机 Intel i7-13700H，Windows，6 个计算线程、单并行调度线程、batch 1。模型顺序执行，未同时争用 CPU。以下排除模型加载、预热、分词、文件读取、解析、OCR、SQLite／Tantivy 写入，查询每条都真正推理，不复用应用查询缓存。

| 具体运行配置 | 同样 482 个正文窗口 | 196 条指令查询的平均编码耗时 |
|---|---:|---:|
| 当前 RWKV 混合 INT8，Rust／ORT | 41.6 秒 | 20.1 ms |
| 官方 RWKV FP32，C 参考实现 | 143.1 秒 | 54.2 ms |
| 本地 Qwen INT8，ORT | 103.2 秒 | 32.2 ms |
| 官方 Qwen 原权重 FP32，PyTorch CPU | 388.2 秒 | 140.6 ms |

当前 RWKV 部署在这组窗口上约为本地 Qwen INT8 耗时的 **40%**。这是两种具体部署配置的观察；模型规模、量化范围、运行时和实现不同，不能解释成架构必然有固定倍数差距。官方 FP32 参考实现也不是各模型最佳 CPU 工程优化结果。

RWKV 计时包含 Rust worker 的请求往返，Qwen 是进程内调用；上表不是完整软件搜索延迟或实际索引耗时，也没有测整本小说的 Qwen 全量索引。短查询计时不能直接外推成长 TXT 的总处理时间。

## 对当前项目的判断

在本轮小型固定资料集上，保留当前 RWKV CPU 部署是合理的成本取舍。Qwen 在中英文对应和部分条款定位上有实际收益，但文件第一名只多一条，新构造用例也没有全面领先；数字、否定、无答案误召回并未随换模型自然消失。

如果后续以更好的段落定位为目标评估 Qwen，应以通过官方对齐验证的模型路径为基础，再测可接受的量化方案和 CPU 成本。是否值得替换，应由新的客户原始文件与未参与调试的查询决定。本轮没有据结果继续修改检索规则，也没有将 Qwen 接入桌面版。

## 复现材料

- 冻结构造集：`scripts/fixtures/rwkv-qwen-cases-20261029.json`
- 统一输入与本地部署对照：`scripts/compare-rwkv-qwen.py`
- 官方 RWKV FP32 对照：`scripts/compare-rwkv-reference.py`
- 官方 Qwen FP32 对照：`scripts/compare-qwen-reference.py`
- 汇总及逐条结果生成：`scripts/summarize-rwkv-qwen.py`
- 冻结全部输入：`.codex-tmp/rwkv-qwen-comparison-20261029/frozen-dataset.json`
- 合并原始结果：`.codex-tmp/rwkv-qwen-comparison-20261029/combined-result.json`
- 官方示例核对：同目录 `qwen-fp32-official-example-check.json`
- 当前软件最终结果：同目录 `application-final/result.json`
- 每条路径的全部向量、计时和日志：同目录相应 `.npz`、`*-timing.json`、日志文件。

官方模型、转换权重及固定索引在本机忽略目录中，脚本不是无需准备资源的公开标准基准。它们只读取测试源索引，不修改现用应用数据。

```powershell
$env:PYTHONIOENCODING = 'utf-8'
cargo build --release -p search-core --example rwkv-embed
python -B scripts/compare-rwkv-qwen.py
python -B scripts/compare-rwkv-reference.py
python -B scripts/compare-qwen-reference.py
python -B scripts/summarize-rwkv-qwen.py
```

脚本会复用身份匹配的向量缓存；需要重测耗时时使用新的输出目录并保持同一冻结输入、线程配置和模型版本。报告原始计时来自本轮首次实际编码，不是缓存命中时间。
