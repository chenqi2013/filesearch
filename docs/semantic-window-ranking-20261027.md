# 片段定位与查询过滤修正（2026-10-27）

## 本轮范围与结论

针对上一轮独立评测暴露的片段错误和误过滤，修改查询侧候选选择、局部证据确认和摘要截取。保持现有 RWKV 模型、CPU 推理路径、v10 索引协议及全部正文语义向量，不重新生成文档 embedding，不增加查询模型推理次数。

同一批 68 条正例回归中，语义和混合的目标文件召回均从 57 条提高到 62 条，首位命中从 55 条提高到 60 条，原已命中的目标没有丢失。三条“关键词能找到而语义/混合漏掉”的查询均找回。部分片段定位得到修正，但并非全部修好；12 条无答案负例仍有原来的 3 条误召回，没有新增误召回文档。

这些查询已用于本轮开发和回归，不再是本轮改动的未见测试集；不能把 91.2% 宣称为产品通用准确率。

本轮已编译 release 搜索核心，但未替换用户正在运行的桌面进程，未制作新安装包。

## 根因与实现

### 过早按文件只留一个窗口

原实现先按原查询向量相似度为每个文件只保留一个窗口，再检查词项覆盖和确认向量。最高原查询分的窗口不一定最切题，确认不通过时还会使文件中的其他有效窗口失去机会。

现在每个语义候选文件保留八个高相似窗口，并补充 BM25 命中原始分段关联的已有语义窗口，再逐个窗口验证和选择。八个只是一次查询的高相似候选配额，不是文档保存或生成向量的上限；关键词补充窗口也可以超过该配额。长文档仍全文生成并保留语义向量。

确认向量、原查询分数和局部词项仍来自同一个窗口；不允许借文件另一处的高分拼出支持证据。

### 结构召回不应强制决定摘要

原来的结构分可能覆盖正文分，并同时把摘要切换成结构所在窗口。例如查询“新加坡”时，大学表格的表头有很高主题相似度，却展示美国/英国的前几名；查询小说情节时，展示与查询无关的早期战斗章节。

现在文档是否可返回与摘要窗口选择分开：先通过正文、结构或词项回退的支持门槛，再从该文件的候选正文窗口中，按双查询相似度的几何平均和 IDF 加权词项覆盖等权选择展示窗口。结构窗口仅作无其他正文候选时的后备来源。IDF 来自现有 Tantivy 索引，不使用领域同义词表。

摘要截取不再停在第一个泛词，而是选择局部词项覆盖更集中的 260 字符窗口；兼容大小写长度扩展，返回文本保持边界限制。英文摘要词项支持简单尾缀 s 的单复数匹配，例如 annotations 对应 Annotation；不改变关键词召回词项和 BM25 排名。

### 过滤需要同窗口的联合证据

对原查询略低、通用确认句较高的窗口，使用联合相似度检查，而不是要求原查询无条件超过统一门槛。无词项重合时，联合相似度要求更严格，防止多窗口选择重新带入日志等偶然相似内容。

词项回退仍需多词匹配；另允许同时满足局部覆盖、IDF 集中度及该窗口双查询相似度的结果进入，修正“月结对账”这类不满足整句/连续短语精确条件的实际内容。不是把所有 BM25 第一名当成高可信结果，也不是全局降低阈值。

## 性能与验证

最终单轮本机 CPU、模型预热后的中位数/P95：语义约 68/119 ms，混合约 37/100 ms，关键词约 18/38 ms。模式顺序轮换，但仍有模型缓存、系统负载和查询长度影响，不能据此宣称普遍加速。

新增工作主要是现有向量窗口比较和局部文本选择。每个查询仍仅使用既有的原查询、确认句两次短文本编码；没有增加文档 embedding 工作量，没有修改索引协议或使向量缓存失效。

- Rust 常规测试：92 通过，5 项默认忽略；新增覆盖多窗口配额与关键词补充、同窗口确认、结构召回的局部摘要、词项集中度、英文复数和 Unicode 摘要边界。
- 两项现有真实 RWKV 模型回归测试分别通过：客户合成语义案例、生产输入形态的 PDF 合同。它们不是客户原文件验收的替代品。
- release 搜索核心构建通过；Rust 格式与相关补丁空白检查通过。
- 评测脚本自动检查：没有原目标丢失、没有关键词排名变化、没有新增负例文档。
- 测试前后源索引、测试快照的文档/向量/持久缓存指纹相同；用户桌面应用未被替换或重启。

## 尚未解决

六条新正例仍未召回指定目标：“出了纠纷去哪个法院”“交货少了应该怎么补”“送过来的东西坏了谁掏钱”“货不对板能不能退回去”“断网以后还能找电脑里的资料吗”“自动识别文件类型并提取元数据的工具”。最后一条返回的中文需求资料也有相关描述，但未找到指定的英文 Tika 文件。

无答案查询“Linux服务器磁盘扩容操作手册”“劳动仲裁申请书模板和填写要求”“Python虚拟环境依赖冲突排查教程”仍误召回；本轮未宣称减少了这三条。

“合同要谁签字才算数”仍显示报价单签字而非合同签署，“文件内容会不会被发到网上”仍展示泛需求内容，“小乌龟吃下蓝色晶体后开始修炼”找到了相关角色与蓝色晶体，但未清楚展示吃下晶体后修炼的动作。因此仍需扩大独立客户查询集，尤其评估片段级相关性，不能仅优化文件级命中率。
